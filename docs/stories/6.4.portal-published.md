# Story 6.4 : Historique des posts publiés côté client

## Status

Done — page « Publiés » du portail (recherche + filtres réseau/période), note de
performance masquée si non partagée, accessible après archivage. 2 tests unitaires +
2 tests d'intégration.

## Story

As a Client,
I want consulter la liste de mes posts déjà publiés,
so that je garde une trace de ce qui est sorti.

## Acceptance Criteria

1. Vue « Publiés » : liste chronologique des posts `published` du client (légende, réseau,
   date, miniature, note de performance si renseignée **et** visible client). ✅
2. Recherche par mot-clé + filtre réseau / période. ✅
3. Reste accessible après archivage du client (compte client actif). ✅
4. Tests d'intégration sur le périmètre. ✅

## Dev Notes

### Décisions

- **`redactClientPost` = garde applicative** : la RLS `posts_select_client` renvoie toute
  la ligne, y compris `performance_note`. Comme le flag `performance_visible_to_client`
  existe déjà (colonne posts, pilotée à l'Epic 9), on masque la note côté service tant
  qu'une vue dédiée n'est pas justifiée. Testé unitairement.
- **Archivage** : `clients_select_contact` (migr 0021) ne filtre pas `is_archived`, et
  `posts_select_client` non plus — un client archivé mais dont le compte contact reste
  actif garde l'accès à ses publiés (AC 6.4.3). Testé.
- **Recherche serveur** : réutilise l'index `search_tsv` (config `french`) déjà en place
  pour la vue interne.
