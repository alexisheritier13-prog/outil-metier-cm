# Stories 4.1 + 4.2: Miniature Canva (auto + fallback)

## Status

Done — Edge Function `canva-preview` déployée et fonctionnelle, composant `CanvaField`
(récupération auto + miniature manuelle + aperçu iframe). 11 tests unitaires (parser) +
4 tests d'intégration verts.

## Stories

**4.1** — As a CM, I want qu'une miniature de preview apparaisse automatiquement quand je
colle un lien Canva, so that je vois le visuel sans quitter l'outil et sans gérer de fichier.

**4.2** — As a CM, I want pouvoir renseigner moi-même une miniature ou afficher un aperçu
embarqué, so that j'ai toujours un visuel même si la récupération automatique échoue.

## Acceptance Criteria

4.1.1 : Edge Function `canva-preview` : reçoit une URL Canva, la `fetch`, extrait `og:image` (fallback `twitter:image`, puis `link rel=image_src`), renvoie l'URL d'image + un statut.
4.1.2 : Déclenchée à la saisie/collage du lien et au clic « rafraîchir » ; asynchrone, **ne bloque jamais** l'enregistrement (NFR6).
4.1.3 : En cas d'échec (lien privé, HTML sans balise, timeout) : erreur typée ; l'UI affiche un message clair + propose la saisie manuelle + l'aperçu iframe.
4.1.4 : Le résultat est stocké sur le post (`canva_thumbnail_url`, `canva_thumbnail_source`, `canva_fetched_at`) ; pas de stockage du binaire.
4.1.5 : Timeout (~5 s), ne suit pas de redirection hors `canva.com`.
4.1.6 : Tests unitaires du parseur (plusieurs échantillons) + test d'intégration de la fonction.
4.2.1 : Champ « URL de miniature (manuel) » ; s'il est renseigné, il prime sur la valeur récupérée automatiquement.
4.2.2 : Bouton « Aperçu Canva » ouvrant le lien en iframe dans une modale.
4.2.3 : Indicateur de la source de la miniature (auto / manuelle).
4.2.4 : Message d'aide rappelant la contrainte « visible par toute personne ayant le lien ».
4.2.5 : Tests unitaires sur la règle de priorité manuel > auto.

## Dev Notes

### Décisions

- **User-agent Slackbot** : Canva renvoie **403** aux navigateurs et à `facebookexternalhit`
  / `Twitterbot`, mais **200 + og:image** à `Slackbot-LinkExpanding`. C'est un crawler de
  dépliage de lien légitime pour ce cas d'usage. Fragilité assumée (cf. archi) : si Canva
  ferme ce chemin, le fallback manuel (4.2) prend le relais.
- **Jamais bloquant** : `fetchCanvaPreview` ne `throw` pas ; l'échec est un état d'UI. Le
  post s'enregistre avec ou sans miniature. Débounce 600 ms à la frappe.
- **Priorité manuel > auto** : si le champ « miniature manuelle » est rempli, il écrase la
  valeur auto (`source='manual'`). Le vider rebascule sur l'auto au prochain fetch.
- **Pas de binaire** : on ne stocke que l'URL de l'image (hébergée par Canva). `<img>` avec
  `loading="lazy"`.
- **iframe** : `sandbox="allow-scripts allow-same-origin"` ; certains liens Canva
  interdisent l'`embedding` (`X-Frame-Options`) → l'iframe peut rester blanche, d'où le
  message d'aide.
- **`canva-parser` dupliqué** front / Edge Function : pas de build partagé Deno↔Vite. La
  version testée est celle du front ; garder les deux identiques (noté dans le fichier).
