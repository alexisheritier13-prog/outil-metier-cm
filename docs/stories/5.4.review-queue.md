# Story 5.4 : File « À valider » (interne)

## Status

Done — page `/app/a-valider`, deux onglets, actions rapides, compteur dans la navigation.
3 tests unitaires + 3 tests d'intégration (157 au total).

## Story

As a Lead CM,
I want une file listant tous les posts en attente de validation (interne et client),
so that je traite les validations sans parcourir le calendrier.

## Acceptance Criteria

1. Page `/app/a-valider` avec deux onglets : « À valider en interne » et « En attente du
   client ». ✅
2. Chaque ligne : client, réseau, date prévue, extrait, ancienneté dans le statut,
   rédacteur ; tri par ancienneté par défaut. ✅ (`status_changed_at` croissant)
3. Actions rapides : ouvrir le détail, valider en interne (lead/admin), relancer le
   client. ✅
4. Filtrable par client ; respecte l'isolation par rôle (un `cm` voit ses clients). ✅
   (la RLS `posts` fait le filtrage ; le `<select>` affine)
5. Le compteur de la file apparaît dans la navigation. ✅

## Dev Notes

### Décisions

- **Pas de nouveau service de file** : `listReviewQueue` réutilise la table `posts` avec un
  filtre de statut ; la RLS garantit déjà qu'un `cm` ne voit que ses clients (AC 5.4.4).
- **Compteur de nav** : `countReviewQueue` compte `internal_review` + `client_review`
  visibles ; requête `head: true` (pas de payload). Rafraîchie à chaque changement de
  statut via l'invalidation `['review-queue']`.
- **« Relancer le client »** = notification in-app aux contacts + trace d'historique.
  L'AC dit explicitement « marque l'alerte, ne fait pas d'email en v1 ».
- **`PostSheet` réutilisé tel quel** pour l'action « Ouvrir » (mêmes props `clients` /
  `authors`).
