so that la base reste propre et je peux diagnostiquer un incident.

## Dev Notes

### Décisions

- **`cron.schedule` appelle directement les fonctions SQL** (`select public.generate_alerts();`)
  — pas de `pg_net` / Edge Function nécessaire, les jobs sont du pur PL/pgSQL.
- **Génération horaire = `generate_alerts()` complet** (idempotent) plutôt qu'une fonction
  partielle « règle g seulement » : plus simple, coût négligeable, et la règle g a besoin
  d'être rafraîchie en journée.
- **Échec → notification (pas alerte)** : l'enum `alert_type_t` n'a pas de valeur
  « système » et `ALTER TYPE ADD VALUE` est délicat en migration ; `notifications.type`
  est du texte libre, on y met `job_failed`. L'Admin le verra dans son flux (page Alertes
  = Epic 8.1 pour les règles métier ; le flux notifications global reste à câbler côté UI,
  mais l'entrée existe).
- **`pg_cron`** : planification vérifiée (`cron.job` : 3 entrées actives). L'exécution
  réelle dépend de l'horloge du serveur ; les tests couvrent le déclenchement manuel et le
  traçage `job_runs`.
