# Stories 6.1 + 6.2 : Coquille de l'espace client + calendrier / détail post

## Status

Done — layout `/portail` isolé (RLS), sélecteur multi-clients, calendrier mois/liste,
détail post en lecture. 3 tests unitaires + 5 tests d'intégration (isolation). 171 tests
au total.

## Stories

**6.1** — un espace dédié qui ne montre que les données de mon entreprise.
**6.2** — voir mes posts sur un calendrier et ouvrir le détail d'un post.

## Acceptance Criteria

### 6.1
1. Routes `/portail/*` réservées au rôle `client` ; layout distinct (logo client, nav
   réduite : Calendrier, À valider, Publiés, Briefs). ✅
2. Toutes les requêtes de l'espace client contraintes par RLS au(x) `client_id` du
   contact. ✅ (`clients_select_contact` migr 0021 + `posts_select_client` 0016 +
   `post_comments_select_client` 0015)
3. Contact rattaché à plusieurs clients → sélecteur ; sinon accès direct. ✅
4. Test central : un contact du client A ne lit aucun post / commentaire / campagne /
   fiche du client B, y compris par appel direct. ✅
5. Contact désactivé refusé. ✅ (`contact_client_ids()` filtre `is_active` → 0 donnée)

### 6.2
1. Calendrier mensuel + vue liste des posts du client, en lecture, statut lisible. ✅
2. Détail post client : réseau, date/heure, légende, aperçu Canva, commentaires `client`,
   statut. ✅
3. Commentaires internes / historique / rédacteur / autres clients jamais exposés. ✅
4. Responsive mobile/tablette. ✅ (header qui se replie, nav scrollable, `PortalPostDetail`
   en `Sheet`)
5. Tests d'intégration sur le filtrage des données exposées. ✅

## Dev Notes

### Décisions

- **La base est la garde** : `portal.ts` n'ajoute aucun filtre `client_id` de sécurité —
  la RLS (`clients_select_contact`, `posts_select_client`, `post_comments_select_client`)
  fait tout. Les filtres applicatifs (`.eq('client_id', …)`) ne servent qu'au périmètre
  d'affichage quand un contact a plusieurs clients.
- **`CalendarView` réutilisé tel quel** avec `editable={false}` — le hook
  `useReschedulePost` est instancié mais jamais déclenché (pas de drag).
- **`PortalPostDetail` distinct de `PostSheet`** : pas d'onglet Historique, pas de
  `StatusActions`, pas de badge de visibilité de commentaire — surface strictement
  réduite (AC 6.2.3).
- **Fiche client archivée reste lisible** : la policy ne filtre pas `is_archived` (AC
  6.4.3 : consultation après archivage tant que le compte client est actif).
