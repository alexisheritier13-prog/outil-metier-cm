# Story 1.1: Initialisation du dépôt et de l'app web

## Status

Review

## Story

**As a** développeur,
**I want** un dépôt Git avec une app React + TypeScript + Vite + Tailwind qui build et se déploie,
**so that** toute évolution ultérieure part d'une base saine et déployée en continu.

## Acceptance Criteria

1: Le dépôt contient une app Vite + React 18 + TypeScript strict + Tailwind + shadcn/ui initialisée, avec ESLint et Prettier configurés.
2: `npm run dev`, `npm run build`, `npm run lint`, `npm run typecheck` et `npm run test` fonctionnent ; `test` exécute au moins un test trivial via Vitest.
3: Une route `/` affiche une page « canari » indiquant la version et l'environnement.
4: Le projet est déployé sur Vercel ou Netlify ; `main` déclenche un déploiement de production, chaque PR une preview.
5: Un workflow GitHub Actions exécute lint + typecheck + tests unitaires sur chaque PR et échoue si l'un échoue.
6: Le `README.md` décrit l'installation locale, les variables d'environnement et les commandes.

## Dev Notes

### Contexte

Projet greenfield. Aucun code existant. Stack imposée par `docs/architecture/tech-stack.md` :
React 18.3 + TypeScript 5.5 + Vite 5.4 + Tailwind 3.4 + shadcn/ui (Radix). Gestionnaire de
paquets : npm. Node ≥ 20 (machine : v24).

### Emplacements (voir `docs/architecture/source-tree.md`)

- Entrée : `src/main.tsx`, routeur `src/router.tsx` (créé minimal ici, étoffé en 1.4).
- `src/lib/` : `utils.ts` (`cn`), `supabase.ts` viendra en 1.2.
- `src/components/ui/` : primitives shadcn.
- `src/styles/globals.css` : directives Tailwind + tokens couleur.
- Tests unitaires : `tests/unit/` (logique pure) et `src/**/__tests__/*.test.tsx` (composants).
  Pour cette story, un test trivial suffit — le placer dans `src/App.test.tsx`.

### Contraintes de `docs/architecture/coding-standards.md` applicables ici

- `strict: true`, `noUncheckedIndexedAccess: true`, pas de `any`.
- Exports nommés uniquement (pas de `export default`) — sauf `App` si requis par un outil ;
  préférer `export function App()`.
- Imports via alias `@/…` (configurer dans `vite.config.ts` + `tsconfig.json`).
- Tailwind uniquement, classes ordonnées (prettier-plugin-tailwindcss).
- `eslint-plugin-jsx-a11y` sans erreur.
- Vues larges : pas de `max-w-*` étroit ni `mx-auto` centré (préférence écran large).

### Détails d'implémentation

- **Version affichée** : injecter la version via `vite.config.ts`
  `define: { __APP_VERSION__: JSON.stringify(pkg.version) }` + déclaration dans
  `src/vite-env.d.ts` (`declare const __APP_VERSION__: string;`). Version de départ dans
  `package.json` : `0.1.0`.
- **Router** : `react-router-dom` v6, `createBrowserRouter` avec une route `/` → `<Canary />`.
  Composant `Canary` dans `src/app/Canary.tsx` (placeholder ; le vrai layout viendra plus tard).
- **shadcn/ui** : ne pas lancer le CLI interactif ; créer manuellement `components.json`,
  `src/lib/utils.ts` avec `cn` (clsx + tailwind-merge) et une primitive `Button`
  (`class-variance-authority`). Dépendances : `clsx`, `tailwind-merge`,
  `class-variance-authority`, `@radix-ui/react-slot`, `tailwindcss-animate`.
- **ESLint** : flat config `eslint.config.js` (ESLint 9) avec `typescript-eslint`,
  `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y`, `eslint-plugin-react-refresh`.
- **Prettier** : `.prettierrc` + `prettier-plugin-tailwindcss`.
- **CI** : `actions/checkout@v4`, `actions/setup-node@v4` (node 20, cache npm), `npm ci`,
  puis `npm run lint`, `npm run typecheck`, `npm run test`. (Les jobs `test:rls` / Supabase
  arrivent en 1.2 — ne pas les ajouter maintenant.)
- **Déploiement (AC 4)** : hors périmètre agent (compte requis). Documenter dans le README
  la procédure Vercel (Framework: Vite, Build `npm run build`, Output `dist`, Rewrite
  `/* -> /index.html`). Laisser la sous-tâche non cochée.

### Testing

- Framework : **Vitest** + **@testing-library/react** + **@testing-library/jest-dom**.
- Config : `vitest` dans `vite.config.ts` (ou `vitest.config.ts`), `environment: 'jsdom'`,
  `setupFiles: ['src/test/setup.ts']` (import `@testing-library/jest-dom/vitest`).
- Test trivial de cette story : `src/App.test.tsx` — rend `<Canary />` et vérifie la
  présence du texte de version (`getByText(/0\.1\.0/)`).
- `npm run test` = `vitest run`. `npm run test:watch` = `vitest`.
