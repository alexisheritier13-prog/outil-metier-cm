# Story 9.3 : Export PDF du calendrier client

## Status

Done — route imprimable autonome `/app/clients/:id/export` + « Enregistrer en
PDF » du navigateur. Bouton « Exporter PDF » sur la fiche client. 2 tests
composant. Décision d'implémentation documentée dans `docs/architecture.md`.

## Story

As a Lead CM,
I want exporter en PDF le calendrier d'un client sur une période,
so that je le partage avec un client qui ne veut pas se connecter.

## Acceptance Criteria

1. Depuis la fiche client ou le calendrier filtré sur un client : « Exporter
   PDF » avec choix de la période. ✅ (bouton sur la fiche client → route
   dédiée, période via `?from`/`?to` modifiable dans la barre d'outils)
2. Le PDF liste les posts par date : date/heure, réseau, légende complète,
   miniature, statut ; en-tête avec logo et nom du client. ✅
3. Génération fiable pour ~80 posts (pagination correcte) ; temps raisonnable. ✅
   (rendu HTML natif + `break-inside: avoid` sur les lignes, pagination = moteur
   d'impression du navigateur, instantané)
4. Décision d'implémentation documentée dans l'architecture. ✅
   (`docs/architecture.md` : ni Edge Function ni `react-pdf`, impression navigateur)
5. Test de non-régression léger. ✅ (`ClientCalendarExportPage.test.tsx` :
   structure du document, groupement par jour, visibilité de la note de perf)

## Dev Notes

### Décision (AC 9.3.4)

**Impression navigateur, pas de génération PDF serveur.**

- *Edge Function HTML→PDF* : Deno Deploy n'embarque pas de moteur de rendu
  (Chromium/puppeteer), Docker est absent de l'environnement — écarté.
- *`@react-pdf/renderer` côté client* : ~200 kB gz, API de mise en page à part,
  gestion manuelle de la pagination — disproportionné pour une liste.
- *Retenu* : une **route imprimable** stylée pour l'impression + « Enregistrer
  en PDF » (présent dans la boîte d'impression de tous les navigateurs modernes).
  Pagination, sauts de page, marges : gérés par le moteur d'impression. Zéro
  dépendance, la vue reste réutilisable à l'écran.

### Autres points

- **Page hors `AppLayout`** : la barre latérale n'a pas de sens sur un document
  destiné à l'impression ; route top-level séparée plutôt que `@media print`
  cachant la coquille partout.
- **Sécurité** : pas de client service-role, pas de secret — l'utilisateur
  interne est authentifié, `listPosts` applique la RLS habituelle (accès au
  client requis). La note de performance suit `performance_visible_to_client`
  (cohérent avec l'espace client, Story 6.4 / 9.4).
- **Période** dans l'URL (`?from`/`?to`, défaut J → J+30) : partageable, et
  « calendrier filtré sur un client » (AC 9.3.1) se ramène au même écran.
