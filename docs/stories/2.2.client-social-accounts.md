# Story 2.2: Comptes sociaux du client

## Status

Done — migration `0003` (networks + social_accounts), onglet « Comptes sociaux » de la
fiche client, 5 tests d'intégration RLS + 3 tests composant verts.

## Story

**As a** CM,
**I want** gérer la liste des comptes sociaux d'un client,
**so that** chaque post peut cibler un compte précis et un réseau connu.

## Acceptance Criteria

1: Migration `social_accounts` (client_id, `network` enum Instagram/LinkedIn/Facebook/TikTok/… extensible, `handle`/nom, timestamps).
2: Sur la fiche client, une section permet d'ajouter/modifier/supprimer des comptes sociaux indépendamment des autres champs.
3: La suppression d'un compte social est définitive mais bloquée (ou avertie) s'il est référencé par des posts non supprimés — comportement défini et testé.
4: Les réseaux disponibles proviennent d'une table de référence `networks` (nom, specs indicatives) éditable par l'Admin.
5: RLS alignée sur l'accès client ; tests d'intégration.

## Dev Notes

### Décisions

- **`network_t` créé dans 0003** (pas dans 0002) : oubli de la migration précédente ; il est
  posé ici et resservira pour `posts` / `campaigns` (Epic 3).
- **Écriture `social_accounts` ouverte au CM assigné** (`has_client_access`), contrairement
  aux champs cœur du client (lead/admin). Justification : donnée opérationnelle dont le CM a
  besoin pour créer ses posts, pas de l'identité du client. Cohérent avec PRD FR7.
- **AC 3 (blocage si référencé par des posts)** : la table `posts` n'existe pas encore
  (Epic 3). Comportement défini : à la création de `posts`, la FK
  `posts.social_account_id`/`(client_id, network)` sera `on delete restrict` et l'UI
  affichera un message. Pour l'instant la suppression est directe, précédée d'un `confirm()`.
  Test du blocage à ajouter avec l'Epic 3.
- **`networks` comme table de référence** plutôt qu'un simple enum figé : permet à l'Admin
  d'éditer les specs indicatives (écran Paramètres → Réseaux, Story 8.3 ou avant). L'enum
  `network_t` reste la contrainte de validité ; `networks` porte le libellé + les specs.
- **NetworkIcon monochrome** : abréviation 2 lettres dans un carré neutre — pas de logo
  couleur dans les listes denses (design N&B en cours ; cohérent front-end-spec §5.2).
