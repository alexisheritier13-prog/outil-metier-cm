# Story 8.3 : Paramètres des seuils d'alertes

## Status

Done — seuils dans `app_settings.alert_thresholds`, page `/app/parametres/alertes`
(Admin), pris en compte par `generate_alerts()`. 3 tests unitaires + 2 tests d'intégration.

## Story

As a Admin agence,
I want configurer les seuils des alertes,
so that l'outil colle au rythme de l'agence.

## Acceptance Criteria

1. Stockage clé/valeur typé des seuils : jours avant relance validation, fenêtre deadline,
   N posts mini, fenêtre trou de calendrier, fenêtre marronnier, fenêtre client inactif. ✅
   (`app_settings` clé `alert_thresholds`, valeurs par défaut matérialisées en migr 0027)
2. Page `/app/parametres/alertes` (Admin) éditant ces valeurs avec bornes de validation. ✅
3. `generate_alerts()` lit ces valeurs ; prise en compte à l'exécution suivante. ✅
   (déjà via `_thr(key, default)` depuis 0026)
4. Tests d'intégration : modifier un seuil change le résultat de génération. ✅

## Dev Notes

### Décisions

- **`app_settings` réutilisé** (déjà key/value jsonb, RLS lecture interne / écriture Admin)
  plutôt qu'une table `alert_settings` dédiée — un seul endroit pour les réglages globaux.
- **Validation de bornes côté front** ; côté base, seul l'Admin écrit (`app_settings`
  policy). `generate_alerts` reste robuste : `_thr` retombe sur le défaut si la clé est
  absente ou non convertible.
- **Regroupement `/app/parametres`** : la nav interne devenait trop longue ; les 3 écrans
  Admin (utilisateurs, seuils, jobs) passent sous un index.

### Emplacements

- `supabase/migrations/0027_alert_settings.sql`

### Testing

- **Unitaire** : valeurs courantes affichées, save appelé avec la valeur modifiée, bornes
  hors limites → bouton désactivé + message, rien pour un non-admin.
- **Intégration** : post en review depuis 2 j → pas d'alerte à seuil 3, alerte après que
  l'Admin abaisse `validation_overdue_days` à 1 ; un CM ne peut pas modifier les seuils.
