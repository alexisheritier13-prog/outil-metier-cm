## Dev Notes

### Décisions

- **Pas de FK sur `origin_id`** (polymorphe : 4 tables cibles) — c'est ce qui permet le
  comportement « origine supprimée » sans trigger : le post garde son pointeur, `describeOrigin`
  renvoie `label: null`, l'UI affiche « origine supprimée ».
- **`describeOrigin` = `switch` explicite** par type (une requête `maybeSingle`) plutôt
  qu'une table de correspondance dynamique — supabase-js exige des noms de table/colonne
  littéraux pour le typage.
- **Sens inverse déjà partiellement là** : `RequestsPage` (Story 6.5) affichait déjà le
  post lié ; on ajoute le bloc pour les idées. Les marronniers donnent un retour au moment
  du « Planifier », un bloc dédié serait du polish.
- **RLS** : `describeOrigin` / `listPostsByOrigin` s'appuient sur la RLS des tables cibles
  (l'utilisateur qui voit le post a l'accès client, donc voit l'origine du même client ;
  une idée globale est visible de tous les internes).
