## Status

## Story

**As a** CM,
**I want** faire évoluer le statut d'un post le long d'un pipeline standard,
**so that** chacun sait où en est chaque contenu.

## Acceptance Criteria

1: Fonction métier `canTransition(from, to, role, post)` centralisant les transitions autorisées du pipeline `brouillon → à valider interne → à valider client → validé → planifié → publié`.
2: Les retours en arrière sont autorisés pour `lead`/`admin` (et `cm` jusqu'à « à valider client » sur ses posts) et journalisés.
3: L'UI n'affiche que les transitions permises pour le rôle courant ; une transition interdite est aussi refusée côté base (trigger ou RPC).
4: Chaque changement de statut crée une entrée d'historique.
5: Tests unitaires exhaustifs de la table de transitions ; tests d'intégration du refus côté base.

## Dev Notes

### Décisions

- **Source de vérité = table SQL `post_transitions`** (pas une fonction figée). `can_transition`
  la lit. Le miroir TS `POST_TRANSITIONS` est la copie ; le test de parité échoue si les deux
  divergent — **toute modif de règle se fait des deux côtés**.
- **Refus du contact client** (`client_review → draft` avec commentaire obligatoire) **non**
  modélisé dans `post_transitions` : la PK `(from, to)` interdit deux lignes, et le refus
  client a des contraintes propres (contact + commentaire). Il passera par le RPC
  `reject_post` (Story 5.3). La ligne `client_review → draft` de la table couvre le retour
  interne (cm/lead/admin, sans commentaire).
- **Garde anti-UPDATE direct** : `post_change_status` étant `security definer` (rôle
  `postgres`), le trigger `posts_guard_status_update` bloque tout changement de `status` où
  `current_user <> 'postgres'`. Les autres champs (légende, date…) restent modifiables
  directement.
- **Commentaire** : stocké dans `post_history` (`action = 'comment'`) faute de table
  `post_comments` (Story 4.5). Le rattachement propre se fera à ce moment-là.
- **`cm` jusqu'à « à valider client »** (AC 2) : couvert — `cm` peut `client_review → draft`
  et `client_review → internal_review` (tirer un post en arrière tant que le client n'a pas
  répondu).
