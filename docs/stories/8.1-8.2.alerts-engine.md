## Dev Notes

### Décisions

- **Table `alerts` séparée de `notifications`** : `notifications` (0017) = événements
  push par utilisateur ; `alerts` = moteur de règles avec déduplication et fermeture
  automatique. Contrats et cycles de vie différents.
- **`dedupe_key`** encode `type + entité + période` (jour pour les règles post-niveau,
  semaine ISO pour les règles client-niveau) → relancer la génération ne double pas, et
  une nouvelle occurrence réapparaît le lendemain / la semaine suivante si le problème
  persiste.
- **Fermeture automatique** limitée aux règles post-niveau (a/b/d/g) : on re-teste la
  condition d'origine ; les règles client-niveau (c/f/e) expirent naturellement via la
  clé hebdo.
- **Seuils dans `app_settings`** (déjà key/value jsonb) plutôt qu'une table dédiée —
  l'UI de réglage = Story 8.3, `generate_alerts` a des défauts codés en dur en attendant.
- **`target_role`** : une alerte marquée `lead` est vue par les leads **et** les admins
  (override), pas par les CM — couvre le « Lead/Admin » de FR36f sans colonne multi-rôle.
