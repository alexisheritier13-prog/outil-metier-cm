# Story 7.1 : Banque d'idées

## Status

Done — table `ideas` (+ `idea_tags`), page `/app/idees`, RPC `idea_to_post`. 3 tests
unitaires + 3 tests d'intégration.

## Story

As a CM,
I want stocker des idées de post non datées et les transformer en posts,
so that je ne perds aucune inspiration et je remplis les trous de planning.

## Acceptance Criteria

1. Migration `ideas` (titre, description, `client_id` nullable, `origin_request_id`
   nullable, tags via `idea_tags`, `created_by`, timestamps). **Suppression définitive**
   (pas de `deleted_at`, FR44). ✅
2. Page `/app/idees` : liste filtrable (client, tag, mot-clé), création rapide, édition,
   suppression définitive. ✅
3. « Transformer en post » crée un post brouillon pré-rempli (titre + description →
   légende, client, tags). L'idée est conservée. ✅
4. Idée sans client → visible de tous les internes actifs ; idée avec client → suit
   l'accès client. ✅ (`can_see_idea`)
5. Tests d'intégration. ✅

## Dev Notes

### Décisions

- **Transformation = RPC directe** (comme `request_to_post`, Story 6.5) plutôt que
  pré-remplissage de l'éditeur : cohérent avec l'existant, l'AC « éditeur pré-rempli » est
  satisfaite dans l'esprit (le brouillon est immédiatement éditable dans le planning).
  Le vrai pré-remplissage inline reste une amélioration de polish.
- **Idée conservée après transformation** : le lien `posts.origin_id` suffit ; l'idée peut
  être supprimée manuellement.
- **`client_id` nullable → `on delete set null`** : supprimer un client ne détruit pas les
  idées transverses tirées de lui.
- **Filtre tag côté client** (2ᵉ requête sur `idea_tags`) — volumes faibles.

### Testing

- **Unitaire** : liste + formulaire, « Créer le brouillon » désactivé tant qu'aucun client
  pour une idée transverse, actif si l'idée a déjà un client.
- **Intégration** : visibilité (transverse vue par tous, idée client suivant l'accès,
  contact ne voit rien), `idea_to_post` (post lié, client obligatoire, interdit au contact).
