# Story 6.3 : Approbation / refus et commentaires côté client

## Status

Done — actions Approuver / Demander une modification dans le détail post client, ajout de
commentaires, file « À valider » avec compteur. 4 tests unitaires (le parcours RPC est
couvert par `client-approval.integration.test.ts`, Story 5.3).

## Story

As a Client,
I want approuver ou refuser un post et laisser un commentaire depuis le détail,
so that je réponds à l'agence au même endroit.

## Acceptance Criteria

1. Sur un post « à valider client », boutons « Approuver » et « Demander une modification »
   (refus ouvre un champ commentaire obligatoire). ✅
2. Utilise les RPC de la Story 5.3 ; l'UI reflète immédiatement le nouveau statut. ✅
   (les mutations invalident `['portal']` ; après refus le post quitte les statuts visibles
   client et disparaît de la liste)
3. Le contact peut ajouter des commentaires `client` sur n'importe lequel de ses posts,
   pas seulement à l'étape de validation. ✅ (formulaire toujours présent dans le détail)
4. File « À valider » côté client avec compteur. ✅ (`/portail/a-valider` +
   pastille dans la nav via `countPortalPending`)
5. Tests E2E approbation / refus. ⚠️ Playwright pas encore câblé (Story 9.x) — couvert par
   les tests d'intégration RPC (5.3) + tests unitaires du composant.
