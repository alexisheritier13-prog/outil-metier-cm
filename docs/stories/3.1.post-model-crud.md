# Story 3.1: Modèle de post et CRUD de base

## Status

Done — migrations `0008`–`0010`, service `posts` + `PostForm` + vue liste provisoire,
6 tests d'intégration + 3 composant verts.

## Story

**As a** CM,
**I want** créer, modifier et supprimer un post avec tous ses champs,
**so that** je matérialise chaque contenu prévu pour un client.

## Acceptance Criteria

1: Migration `posts` : id, client_id, `network`, `scheduled_at` (timestamptz, fuseau Europe/Paris géré à l'affichage), `caption`, `canva_url`, `canva_thumbnail_url`, `canva_fetched_at`, `status` enum (pipeline FR12), `author_id` (CM), `campaign_id` nullable, `performance_note`, `deleted_at` nullable, timestamps.
2: Formulaire de création/édition (client requis, réseau requis, date/heure requise, légende) avec validation Zod ; date affichée et saisie en heure de Paris.
3: Un `cm` ne peut créer un post que pour un client assigné ; `lead`/`admin` pour tout client actif ; RLS + tests.
4: `author_id` par défaut = utilisateur courant, modifiable par `lead`/`admin`.
5: La suppression pose `deleted_at` (corbeille) selon les règles FR45 ; les posts avec `deleted_at` sont exclus partout par défaut.
6: Tests unitaires sur la validation du formulaire et tests d'intégration sur les droits de création/suppression.

## Dev Notes

### Décisions

- **Colonnes complètes dès 0008** (front-load) : `campaign_id` (nullable, **sans FK** —
  ajoutée en 3.6), `origin_type/origin_id`, `performance_*`, `canva_*`. Les stories 3.2–3.7
  ajoutent surtout du comportement, peu de colonnes.
- **`0010` — incompatibilité soft-delete / RLS** : découverte via le test soft-delete.
  PostgreSQL applique la visibilité SELECT à la ligne modifiée : une policy
  `using (deleted_at is null ...)` fait échouer l'`UPDATE deleted_at = now()` avec
  `42501 new row violates row-level security policy`. Corrigé pour `posts` **et** `clients`
  (même bug latent). Le contrat archi (« corbeille = vue dédiée ») reste tenu côté app.
- **`0009` — lecture des profils internes** : le modèle 1.3 limitait `profiles` à
  self + admin. L'Epic 3 a besoin que tout interne voie les autres internes (rédacteur,
  file de validation). La cloison qui compte (`client` ne voit pas les internes) est
  préservée. Test 1.3 « le CM ne lit pas le profil du lead » mis à jour.
- **Transitions de statut** : pas de contrôle fin ici (RLS update laisse passer). La
  fonction SQL `can_transition` + les RPC arrivent en Story 3.2. Le miroir TS
  (`src/shared/utils/transitions.ts`) existe déjà.
- **Fuseau** : `scheduled_at` stocké UTC. `PostForm` convertit le `datetime-local`
  (heure murale de Paris) via `parisWallTimeToUtc`, et reconvertit UTC→Paris pour
  l'affichage/l'édition. Gère l'heure été/hiver (testé).
- **Vue liste provisoire** : `/app` montre une liste de posts (CRUD complet = vertical
  slice). Story 3.3 la remplace par le calendrier FullCalendar.
